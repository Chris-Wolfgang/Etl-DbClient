 1// Coyote systematic-testing driver for DbCommandBuilder's SQL cache.
 2//
 3// The cache is a ConcurrentDictionary<Type, TypeMetadata>. Concurrent
 4// consumers of the same TRecord race each other on first access — the
 5// invariant is: every thread ends up with the SAME SQL string (equal by
 6// value; ideally reference-equal via the cache). Coyote's scheduler
 7// explores thousands of interleavings of those concurrent calls,
 8// covering paths that a "run this test 10 000 times" stress test would
 9// never reproduce reliably.
 10//
 11// Coyote's engine works without IL rewriting for tests that use
 12// `TestingEngine.Create(config, action).Run()` directly — the engine
 13// takes control of the scheduler for the duration of `action`. That's
 14// what these xunit facts do. If we ever want the deeper systematic
 15// coverage that rewriting provides (every `await` intercepted, not
 16// just the ones inside our test action), a follow-up can add a
 17// coyote-rewrite step to the CI build pipeline.
